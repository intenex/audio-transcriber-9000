# Development Guide — Rules, Best Practices, Gotchas

How to work on this codebase without regressing it. Read [ARCHITECTURE.md](ARCHITECTURE.md) first; verification lives in [TESTING.md](TESTING.md).

## Workflow rules

1. **`xcodegen generate` after adding/removing/moving any source file** (or editing `project.yml`). The `.xcodeproj` is generated; never hand-edit it. Build failures like "Build input file cannot be found" mean you forgot this.
1a. **Two app targets share one module.** `AudioTranscriber9000` (macOS) and `AudioTranscriber9000iOS` (iOS 17+, bundle `com.audiortranscriber.AudioTranscriber.ios`) compile the same sources with `PRODUCT_MODULE_NAME: AudioTranscriber`; each excludes the other's `App/*`/`Views/*` folders and `Info*.plist`. Platform-specific code uses `#if os(...)`; UI lives in `Views/Mac`, `Views/iOS`, `Views/Shared`. **Every commit must keep BOTH platforms building** (Mac: build+test; iOS: `-scheme AudioTranscriber9000iOS -destination 'platform=iOS Simulator,name=iPhone 17'`). Mac-only: LocalMLX chat (child processes), NSSavePanel/ffmpeg exports. The wiring order lives once in `AppBootstrap.wire` — both scenes call it.
2. **Commit small and green.** One logical step per commit; build + `xcodebuild test` must pass before each commit. This repo's history is the template — follow it.
3. **TDD the pure logic.** Anything computable without models/network/UI (planners, mergers, parsers, stores, math) gets unit tests written with or before the implementation. Pure logic lives in `enum`/`struct` helpers precisely so it's testable — keep it that way when adding features.
4. **Verify end-to-end before claiming done.** Unit tests are necessary, not sufficient. Use the gated integration tests (marker file — see TESTING.md) and launch the app. Two bugs in the overhaul (token gluing, diarizer over-splitting) passed every unit test and only surfaced on real audio.
5. **Session end**: run the mandatory checklist in CLAUDE.md / AGENTS.md (build, tests, launch + osascript verification, honest report).

## Invariants — do not break these

- **Sidecar formats are frozen** (`.md`, `.segments.json`, `.speakers.json`, `.summary.json`, `.chat.json`). Pre-overhaul files must keep loading. If you must evolve one, decode-with-fallback (see `TranscriptionSegment.init(from:)` tolerating missing `words`). New sidecar? Add it to `Recording.allSidecarURLs` or deletion will leak it.
- **`TranscriptionEngine` contract** (ARCHITECTURE.md): normalized `SPEAKER_%02d` labels, Task-cancellation honored, checkpoint resume, monotonic progress. The queue, UI, speaker library, and formatter all assume it.
- **Checkpoint chunk plans are immutable on resume.** Never recompute the plan for an existing checkpoint — VAD nondeterminism or config drift would misalign completed chunks. Changing checkpoint semantics ⇒ bump `TranscriptionCheckpoint.currentVersion` (old checkpoints are then discarded, which is safe).
- **`TranscriptionStatus` decoding is tolerant** (unknown → `.pending`). Keep it that way; old manifests must never fail to load. Every `switch` over the enum is exhaustive — the compiler walks you through new cases.
- **Secrets go in Keychain**, never UserDefaults. New key ⇒ add a `SecretKey` case. New UserDefaults key ⇒ add it to the inventory in ARCHITECTURE.md.
- **recordings.json is a rebuildable cache; `.meta.json` is the durable metadata source.** Code must survive a deleted/corrupt manifest (orphan adoption + meta sidecars rebuild it, stable UUIDs included). Metadata edits (name/category/engineUsed) must go through `store.update`/the category APIs — direct array mutation would leave the sidecar stale. Don't add state that can't be reconstructed or tolerated as lost.
- **All library writes are atomic via `AtomicFile`** — never `data.write(to:)` a sidecar directly; partial files must be unobservable (sync agents upload mid-write otherwise).
- **Checkpoints live OUTSIDE the library** (`CheckpointLocation`: Application Support, keyed by recording UUID) — they're rewritten every chunk and are device-local. Never derive a checkpoint path from the audio stem; `Recording.checkpointURL` is the only source. Stable UUIDs (via `.meta.json`) are what make ID-keying safe.
- **Never stream a growing file into the library.** The active recording, in-flight compressions, and imports write into the device-local spool (`SpoolLocation`, Application Support/InProgress) and are **renamed** into the library only after the container is finalized and verified. Real-mic flow verified by the gated `RecorderSpoolIntegrationTests`.
- **The spool sweep must never touch live capture files.** `sweepSpool` (salvages crash leftovers >4 KB at load) skips (a) `store.activeRecordingURL`, (b) anything sharing the active recording's stem — the recorder's per-configuration segments `<stem>.segN.<ext>` live beside it, and (c) **anything modified <60 s ago** (cross-instance protection: another RecordingStore — a second app instance, the test host's live app services — can't know this instance's active URL; a growing capture keeps its mtime fresh, a real crash leftover is stale by the next load). Learned the hard way: the pre-guard sweep, triggered by a cloud-watcher reload in a stale running app instance, moved live segment files out from under the writer mid-recording.
- **Recorder resilience invariants** (AudioRecorder): capture interruptions rotate to a NEW segment file — never write a different format into an open AVAudioFile, never convert in the tap; the offline stitch (`AudioCompressor.concatenateSync`) is the only place formats merge. On unrecoverable rebuild failure, stop and SAVE what exists — a recorder must never lose captured audio silently. Any code path that ends capture must surface it (errorMessage / status bar), because macOS stops engines silently.
- **Guardrail invariant: uncertainty always means "there was sound".** The silence auto-stop (`SilenceDetector`) may only fire on an unbroken stretch where *every* buffer failed all three sound rules; one sounding buffer, a capture rotation, or an unmeasured gap resets the clock. Never widen a threshold or make a rule "smarter" without adding cases to `RecordingGuardrailTests` **and** re-running `SilenceDetectorRealAudioTests` (which replays the fixture, a −30 dB whisper copy, and — gated — the user's entire real library: longest observed silence run 1.1 s / 3.2 s against a 1200 s limit). A check-in that goes unanswered must never stop a recording by itself. Auto-stop is always stop-**and-save**, with a visible message plus a notification.
- **Destructive audio operations verify before they replace.** Trim and compress both write into the spool, check the result's duration against the source, and only then swap — the original is never removed first. Trims keep the same URL/stem so sidecars stay attached, and only ever cut *after* the last detected sound plus padding. Unfinalized containers (no readable duration) never enter the library; they go to `Application Support/AudioTranscriber/Unfinished/` and are kept.
- **A library reload must never clobber live in-memory state.** `RecordingStore.load()` is not just a launch path — every iCloud change reloads the library from disk at an arbitrary moment. Its repair pass therefore skips anything the app is working on right now: `inFlightTranscriptionIDs` (maintained by `TranscriptionService` from enqueue to job end) keeps `.processing`, and `activeRecordingURL` protects live capture. Any future long-running operation that lives in memory must claim its recording the same way. This was a real bug: pressing Transcribe wrote `.meta.json` → the watcher reloaded → the repair pass demoted the running job to `.pending`, so the whole app showed "Ready to transcribe" while the transcription ran to completion invisibly.
- **The sync watcher must ignore its own echo.** Every `AtomicFile.write` records the file name (`AtomicFile.noteSelfWrite`); `CloudSyncManager` reloads only for batches containing at least one name it did not just write. Without this, ordinary status churn triggers a full library reload (which stats and duration-probes every file) seconds after every write.
- **iCloud sync invariants**: the manifest cache and checkpoints stay OUT of the synced tree; every in-container write goes through `AtomicFile` (which adds `NSFileCoordinator(.forReplacing)` there); placeholder stubs (`.name.icloud`) count as existing files — evicted ≠ deleted; `LibraryMigrator` must stay abort-safe (idempotent copies, verify before repoint, never delete the local originals). All sync logic must remain testable against `LocalFolderSyncEngine` — never require real iCloud in unit tests.
- **KeychainStore is dual-layer**: synchronizable shared-access-group items first, legacy device-local fallback when signing lacks the entitlement. Never remove the fallback — dev/ad-hoc builds and the transition period depend on it. The service string and access group are fixed constants (iOS has a different bundle id).

## Concurrency rules (violations here were real crashes)

- **Swift exclusivity with @Observable stores**: never call anything that *reads* `store.recordings` (e.g. `store.recording(with:)`, `statusForExistingCheckpoint`) from **inside** a `store.update { }` closure — `update` holds exclusive `inout` access to the array and you get a runtime "Fatal access conflict". Compute values before the closure.
- **Never block the cooperative pool.** Synchronous heavy calls (e.g. `performCompleteDiarization`) go through `withCheckedThrowingContinuation` + `DispatchQueue.global`. 
- **Every `Process` must have both pipes drained continuously** (readabilityHandler or equivalent) — a full 64 KB pipe deadlocks the child forever. This exact bug was why long transcriptions never finished pre-overhaul, and it existed a second time in the old LLM service's stderr. Also: retain the `Process`/`Task` so it can be cancelled, and wire `continuation.onTermination` to kill children.
- **Timeouts must not depend on receiving data.** Waiting loops poll a buffer + deadline (see `MLXServerProcess.waitForReady`) rather than `for await` alone — a silent child means no chunks means a dead deadline check.
- **AVAudioEngine**: hardware init off the main thread (TCC deadlock); no format conversion inside the tap callback (historic `ExtAudioFile::WriteInputProc` crash) — the `AVAudioFile(… commonFormat:)` trick converts internally instead; don't reuse an `AsyncStream` across cancelled iterations (single-consumption; cancellation finishes the continuation).
- **Large-file reads**: a single `AVAudioFile.read`/`ExtAudioFileRead` fails with coreaudio **error -40** once the requested payload exceeds ~2 GB (internal 32-bit overflow) — any recording over ~3 h of Float32/48 kHz. Always read in windows; use `WindowedAudioLoader` (persistent AVAudioConverter across windows, so no resampler seams).
- **AVAudioFile finalization**: compressed containers (m4a) are only finalized when the `AVAudioFile` deinits — reading the file (afinfo, duration, transcription) before releasing the writer yields error `1685348671`/zero duration. The recorder nils `audioFile` before inserting into the store; keep that ordering.
- **Never trust manifest metadata over the file.** Durations migrated from the pre-overhaul app can be wildly wrong (a 2 h 07 m file stored as 4 h 05 m — old timer-accumulation bug). `RecordingStore.load()` heals durations that deviate >2 % from the audio header, and any verification (e.g. compress-in-place) must compare against `audioDuration(for: fileURL)`, never `recording.duration`.
- **Never use AVAssetReader on this app's WAVs.** Some older-build WAVs have quirky headers that AVAssetReader silently truncates (a 2 h file "ended" after ~2.5 min) while AVAudioFile reads them completely. ALL audio reading — transcription loads, compression, clip extraction — goes through AVAudioFile-based paths (`WindowedAudioLoader`, the rewritten `AudioCompressor`). Duration-verify any transcode before deleting a source.
- **Reasoning-model output**: MiniMax-M3 streams `<think>…</think>` INSIDE `content` deltas (plus a parallel `reasoning` field) and its default token budget lets it churn for many minutes — always send `max_tokens`, route think spans through `ThinkTagFilter`, and parse structured outputs with `strippingThinkBlocks()` + balanced-brace extraction (`SummarizationService`).
- **Voice clips must pass a speech gate** (`ReferenceClipExtractor.isLikelySpeech`, RMS ≥ 0.004) before enrollment, and written clips are re-verified after encoding; Settings → Speakers has "Clean Up Silent Clips" for legacy bad clips.
- **Never mutate view state synchronously inside a text field's `onChange(of: value)`** — the re-render can restructure the container hosting the active field editor and revert an in-progress paste (macOS SecureField). This emptied API-key fields mid-paste, and the then-destructive `KeychainStore.set("")` deleted the key. Rules now enforced: `set` with empty input is a no-op (delete is explicit only), saves are debounced off the edit path, and the field's trailing icons toggle via `.opacity`, never insertion/removal. Verified by `KeychainFieldLiveTests` (in-process — AX cannot focus SwiftUI SecureFields).
- **NSViewRepresentable coordinators outlive selection changes.** SwiftUI reuses the NSView + Coordinator when the detail view switches records — any closure or content captured at `makeCoordinator`/`makeNSView` time goes stale. Re-assign closures in `updateNSView` and key content rebuilds on an explicit `contentID`, not on data shape (two recordings can have identical segment counts). This exact bug made transcript clicks play the previously viewed recording.

## FluidAudio gotchas (pinned `exactVersion: 0.12.4` — re-verify all of these on upgrade)

- `TokenTiming.token` is **pre-normalized**: SentencePiece `▁` already replaced with a **leading space**. Word assembly splits on `hasPrefix(" ")` (`WordTimingAssembler`). Splitting on `▁` glues an entire chunk into one giant "word", which cascades into 1 segment / 1 speaker.
- `DiarizerConfig.clusteringThreshold`: **higher = more merging = fewer speakers** — the library's doc comment implies the opposite. App default **0.85** (UserDefaults `diarizationClusteringThreshold`); library default 0.7 split a real 2-speaker phone call into 4. Tuning harness: `DiarizerThresholdSweepTests`.
- `DiarizerModels` is `consuming` on `initialize` — you can't reuse the models value; reload via `downloadIfNeeded()` (disk-cached, fast) when rebuilding the manager.
- Model caches: `AsrModels.defaultCacheDirectory()`, `DiarizerModels.defaultModelsDirectory()` (~1.5 GB total). First *build* needs network once (binary xcframework dependency).
- Measured baselines on this M1 Max (update if hardware changes): 63 s file ≈ 2.4 s warm; 2 h 07 m file ≈ 142 s (53×); diarization included.

## Recipes

**Add a transcription engine**: new `TranscriptionEngineKind` case → implement `TranscriptionEngine` (normalize speakers, honor cancellation, map provider errors to `CloudTranscriptionError`) → register in `AudioTranscriberApp`'s `cloudEngineFactory` → add `SecretKey` + Settings field (`KeychainSecureField`) → cost constant in `TranscriptionCostEstimator` → menu entries in `TranscriptionView.transcribeMenuItems` + `RecordingListView.rowContextMenu` → mocked-flow unit test (MockURLProtocol; see `AssemblyAIEngineFlowTests`).

**Add a chat provider**: if it's OpenAI-compatible, just instantiate `OpenAICompatibleChatProvider` in `ChatService` with base URL/model/key closures + Settings section + `ChatProviderID` case. Anything else implements `ChatProvider` directly (stream events, respect `contextCharacterBudget`).

**Add a sidecar file**: helper URL on `Recording`, append to `allSidecarURLs`, decide load/save owner, add round-trip test.

**Touch the UI shell**: keep `TranscriptionView` state switches exhaustive; anything status-related must handle `.paused`/`.partial`; new environment objects must be injected in **both** scenes in `AudioTranscriberApp`.

## Known limitations / future work

- Cloud engines are verified against mocked HTTP only — live-key smoke tests still pending (needs user's keys; run one short + one long recording through OpenAI and AssemblyAI when keys exist).
- OpenAI multi-part uploads: >4 concurrently-present speakers can fragment identity across parts (reference cap is 4) — accepted; pills rename merges.
- Attribution: cloud transcription attribution is engine-level (`modelDescription`); AssemblyAI doesn't expose a finer model name in responses we parse.
- Speaker library "re-embed from clips" (after a FluidAudio model upgrade) is not implemented — enrollments would need re-creating from source recordings.
- ElevenLabs Scribe is the natural third cloud engine if wanted (follow the engine recipe).
- `AudioRecorder`'s tap-local `firstWriteError` capture is technically an unsynchronized cross-thread read (benign in practice with the 300 ms margin) — tidy if you're in there anyway.
